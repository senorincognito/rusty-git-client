# Worktrees: design notes

What the user sees is in `docs/features/worktrees.md`.

- **Backend** (`sidebar/worktrees.rs`): system `git worktree` through `run_git` (libgit2's worktree support is thin; `run_git` also puts the calls in the command log). `get_worktrees` parses `git worktree list --porcelain` (no `-z`: that needs git 2.36; a path with a newline would break it). Paths go through `normalize` (canonicalize, strip `\\?\`) so they equal `RepoInfo.path` and a worktree opens as a tab with plain `open_repo`; git prints `C:/...` on Windows. The first record is the main working directory (`isMain`); `isCurrent` compares the open tab's workdir.
- **Where they go**: `<main>.worktrees/<branch with / as ->` beside the main working directory, never inside it (would be untracked files) and not in the app data dir (the user wants to find the folder, and agents' tools should be able to reach it). Not configurable yet.
- **Branch rule**: an existing local branch is checked out as it is, otherwise `-b <branch>` from the HEAD of the worktree the command ran in. The "already checked out elsewhere" refusal is git's own message, shown as it is.
- **Remove** never touches the branch. Without `--force` git refuses a dirty worktree; the UI recognises that message (`isDirty` in `Worktrees.tsx`, so it depends on git's wording) and offers a second confirmation for `--force`. A locked worktree needs `--force --force` and stays refused, with git's message.
- **Outside the undo journal** (like tags and files): a worktree is a folder, which snapshots don't cover.
- **Watcher** (`repo/watch.rs`): a linked worktree's git dir (`.git/worktrees/<name>`) holds only its HEAD and index, so `refs/` is watched in `commondir()`.
- **Tabs**: `RepoView` gets `onOpenRepo` / `onCloseRepo` (App's `openTab` / `closeTab`). Only the active tab is mounted, so a background worktree tab has no watcher: it reloads when you switch to it.
- **Branches held elsewhere** (`branches_held_elsewhere`, `refuse_if_held`): read with git2 by opening the main repository (`commondir()`) and every linked one via `open_from_worktree`, then each HEAD; no process, because `get_graph` and `get_local_branches` ask on every load. This is a safety check, not only wording: libgit2's `set_head` happily checks out a branch another worktree holds, which would leave two HEADs on one branch. It guards `checkout_branch`, `rename_branch` (which would otherwise leave the other worktree's HEAD dangling), `delete_branch_checked`, and `delete_synced` / the clean-up list skip such branches. `BranchInfo.worktree` and `RefLabel.worktree` (branch labels only) carry the path; the graph's own checkout still offers the label and shows the refusal.
- **Change counts** (`count_worktree_changes`): `changes::status_of` per worktree on scoped threads, keyed by path; separate from `get_worktrees` so the list never waits for a big tree. Refreshed with the list and on window focus; other worktrees' indexes aren't watched, so a commit made there shows up on the next focus.

## Agents in worktrees

Goal: one agent per worktree, running in parallel, visible without switching tabs, and its branch brought back with the existing merge tools. Built as the five steps below.

**Why step 1 was needed.** The app had one PTY session and `TerminalPanel` stopped it on unmount. Only the active tab's `RepoView` is mounted, so switching tabs killed whatever ran in the terminal, an agent included.

1. **Terminal sessions owned by the backend** (`terminal/mod.rs`).
   - `Terminal` is a map of sessions keyed by the working directory's path. `term_start(path, cols, rows, restart)` is start-or-attach and returns `{ id, seq, replay, exited, agent }`; `term_detach(path)` when the panel unmounts; `term_stop(path)`; `term_write`/`term_resize` address a session by its `id` (a restart gets a new one, so stale events and keystrokes are dropped); `term_list` for the dots.
   - The reader thread keeps the last 256 KB of output (`Output`, whole chunks dropped from the front) and numbers every chunk (`seq`). `term_start` marks the session attached and snapshots the replay under the same lock, so every chunk is either in the replay or sent live afterwards; the frontend holds back events that arrive while attaching and drops those with `seq` up to the replay's. Live `term-data` events are only emitted while a panel is attached.
   - **ConPTY cursor query**: with no panel nobody answers `ESC[6n`, and ConPTY waits, so the reader thread answers it while unattached. It is also stripped from the stored output, or the next panel's xterm would answer the replayed query into the shell. For the same reason `TerminalPanel` drops `onData` while it writes the replay (xterm answers other queries too).
   - After attaching to a session with an agent, the panel resizes the PTY by one column and back so a full-screen TUI redraws over the replay. **Untested with a real agent**: the replay of a TUI that has been in the alternate screen for long may look off until it redraws.
   - Sessions end with their tab (`App.closeTab` calls `term_stop`, asking first when an agent runs), with their worktree (the removal stops it: a shell in the folder would block deleting it on Windows), or with the app. A plain shell of a tab you left keeps running.
   - Closing a tab is async now (`closeTab` awaits the confirmation).
2. **Agent presets** (a list, not one command).
   - A preset is `{ name, command }` (`useAgentPresets` in `hooks/useSetting`, localStorage `agents.presets`; examples `claude`, `codex`, `aider`, `pi` that the user can delete). Edited in the Settings dialog; the first is the default (reordering instead of a separate "default" mark). Rows with an empty name or command are kept in the list but ignored (`usablePresets`).
   - **Start agent ▸ <preset>** in the worktree's context menu, plus a checkbox (and a choice when there are several) in the New worktree form. `term_run(path, command, agent)` starts the session without a panel if needed (120x30), types `command` + `\r` and records the agent name; the shell stays open when the agent quits. It refuses while an agent is recorded for that path (the text would go to the agent): **Stop terminal session** clears it.
   - The CLI must already be installed, on PATH and signed in; the app only runs the command. `check_agent_commands` (`terminal/agents.rs`) looks each program up: on Windows by scanning `PATH` with `PATHEXT` (the app inherits the user PATH), on macOS by asking the login shell (`command -v`; a Dock-launched app has not read the profile). Commands with shell characters aren't checked. A missing program only warns in the tooltip and does not disable the entry, because PowerShell may know an alias or function this can't see.
   - Any terminal agent works, local-model ones included (Ollama / LM Studio are the agent's own configuration).
   - No task prompt at launch for now: it needs a per-preset template (`claude "{prompt}"` vs `aider --message "{prompt}"`) plus quoting for PowerShell, cmd and bash. A `{prompt}` placeholder can be added later without changing the design.
3. **Status without switching tabs.**
   - `hooks/useTerminalSessions` polls `term_list` every 2 s for the whole app (one timer while any component subscribes) and turns the idle time into *working* (< 3 s since output), *idle* or *exited*. It only re-renders when a status changes. The dot (`components/AgentDot`) is on worktree rows and tabs, for sessions that have an agent. A heuristic on output only, the same for every agent: "idle" cannot tell finished from waiting for an answer, and stays idle after the agent quit and left the shell.
   - While an agent runs in a listed worktree, `Worktrees` refreshes the change counts every 10 s (other worktrees' indexes aren't watched).
   - A tab with an agent session opens its terminal by itself (`RepoView` asks `term_list` on mount).
4. **Merge back** (wiring; a worktree's branch is an ordinary branch).
   - Worktree context menu: **Merge into `<current>`** and **Rebase `<current>` onto …** via `RepoView`'s `onMerge` / `onRebaseOnto`, which also bring the conflict view. Uncommitted files in the worktree are mentioned in the tooltip.
   - **Finish…** (in `Worktrees.finish`): confirmation listing the three steps, `mergeBranch`, then (unless it stopped on conflicts) `term_stop`, `remove_worktree_cmd` without force, `delete_local_branch`. Merge commit, as the other merge commands do. Refused while the worktree has uncommitted files (so the removal can't lose anything). A failure after the merge says the merge is done and what failed.
5. **Tests**: the terminal test now starts a session without a panel and checks that the backend answers the cursor query, keeps the output for the replay without the query, and only emits live events after `attach`; plus the scrollback trimming and the PATH lookup. Nothing here is covered end to end with a real agent or in the running UI.

Not built: a task prompt at launch (needs a per-preset template such as `claude "{prompt}"` vs `aider --message "{prompt}"` and quoting for PowerShell, cmd and bash).
