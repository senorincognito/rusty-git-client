# Rusty Git Client 0.4.0

The fourth release of Rusty Git Client. It adds **worktrees** (a second working directory with its own branch, opened as a tab) and, on top of them, a way to **run an AI agent in each worktree in parallel** and bring its work back. It also brings a **Settings** dialog, **branch and tag suggestions in the terminal**, and a **list of the git commands** the app runs.

## Requirements
- **Git** installed and on your `PATH` (the app runs the system `git` for fetch, pull, push and worktrees).
- Windows needs the WebView2 runtime (included in Windows 11).
- To run agents: the agent's program (for example `claude`) installed, on your `PATH` and signed in. The app only types its command into a terminal.

## Downloads
- **Windows:** the setup installer (`…_x64-setup.exe`), the MSI, or the standalone `rusty-git-client.exe`.
- **macOS:** the `.dmg`, as built by the release pipeline.
- The builds are **not signed**. Windows SmartScreen shows "unknown publisher" (choose *More info*, then *Run anyway*), and macOS needs right-click, then *Open*, the first time.

## Before you update
- Nothing to do: saved settings and the recent-repositories list carry over.

## What's new in 0.4.0

### Worktrees
- A **Worktrees** section in the Branches tab lists the main working directory and every linked one, with its branch and folder. **Click one to open it in its own tab**: graph, changes and terminal then work on that folder.
- **New worktree…** (the section's "⋯" menu) checks out a branch in its own folder, `<repo>.worktrees/<branch>` next to the repository, so it never shows up as untracked files. An existing branch is used as it is; a new name creates the branch from the current commit.
- **Remove worktree…** deletes the folder after a confirmation (the branch is kept), and offers to force it when the worktree has uncommitted files. **Prune missing worktrees** forgets folders deleted by hand.
- A number beside each worktree shows how many files have uncommitted changes in it.
- A branch that another worktree has checked out is marked in the branch list and in the graph. **Checking it out, renaming or deleting it is refused** with a message naming that worktree, and the clean-up commands skip it. (A branch can only be checked out in one working directory.)

### Agents in worktrees
- **Agents** are set up in Settings: a name and the command typed into the terminal, with Claude Code, Codex, Aider and pi to begin with. Add, edit, remove and reorder them; the first is the default.
- **Start agent** (right-click a worktree, or the *Start an agent in it* checkbox of New worktree…) types the command into that worktree's terminal, which runs in the background: several agents can work in parallel while you stay in your tab.
- A **dot** on the worktree and its tab shows how the agent is doing: *working* (it printed something in the last few seconds), *quiet* (still running but printing nothing: maybe waiting for you), *finished* (green: the program ended and the terminal is still open; you can start another there) or *ended* (the terminal session exited). Opening the worktree's tab opens its terminal and shows what the agent printed so far.
- **Merge into … / Rebase … onto …** (right-click a worktree) bring its branch into the branch checked out in your tab, with the usual conflict view. Only commits count, so you are warned first when the worktree still has uncommitted files.
- **Finish…** merges the branch, then removes the worktree (stopping its terminal) and deletes the branch, after one confirmation that lists the steps.

### Terminal
- **Terminal sessions now stay alive** while you look at another tab or hide the panel: a long build or an agent keeps running, and showing the terminal again replays what it printed. Closing a tab ends its session (after asking while an agent runs in it); sessions also end when the app closes.
- **Branch and tag suggestions:** while you type a git command that takes a ref (`checkout`, `merge`, `rebase`, `cherry-pick`, ...), a list of matching branches, remote branches and tags appears at the cursor. `Tab` inserts the highlighted name, `↑` / `↓` choose, `Esc` closes it. It can be turned off in Settings.

### Settings
- A **Settings** dialog (the ⚙ at the right end of the tab bar, or `Ctrl`/`Cmd` + `,`) holds the agents and the terminal suggestions switch. Every change is saved at once.

### Git command list
- A **Commands** button in the title bar shows every call the app makes to the `git` program: the command, the folder, the result and how long it took, with git's output on click. It also shows what runs in the background, such as auto-fetch.

## Known limitations
- The agent's **dot is a guess from the terminal's output and its processes**: *working* and *quiet* cannot tell "thinking" from "waiting for an answer", and *finished* appears a few seconds after the program ends.
- When you return to an agent with a full-screen interface, the terminal replays its output and nudges it to redraw; the screen may look off for a moment.
- There is no task prompt at launch (you type the task into the agent's terminal), and no setup command after creating a worktree: a fresh worktree has no `node_modules` or `target/` yet.
- A program that is not found on your `PATH` only shows a warning in the agent's tooltip; your shell may still know it.
- Changes to the other worktrees' files and indexes are not watched: their change counts refresh when the app regains focus and every ten seconds while an agent runs. Worktree changes are not covered by Undo.
- Conflicts in rebases, cherry-picks, reverts and merges started with uncommitted changes are cancelled (the files are named); resolve them in the terminal.
- The Files tab edits plain text only: no syntax highlighting, no renaming or deleting folders, and edits made there are not covered by Undo. A path with spaces is not quoted in a terminal reference.
- Not built yet: pushing tags, unstaging a single line, syntax highlighting and intra-line diff highlighting in diffs.
- Undo and Redo only cover what you do in the app, and only while it is open. Fetch, push and changes to remotes (including deleting remote branches) cannot be undone.
- Dropping, moving or resetting commits needs a clean working directory.
- Switching repository tabs does not keep a tab's open diff or selected commit (its terminal session is kept).
- Only English.
