# Rusty Git Client 0.3.0

The third release of Rusty Git Client. It adds a **Files tab** to browse, read and edit the working directory (with line-by-line blame and a way to point an AI tool in the terminal at exact code), merge conflict resolution, commit search, tags, Git hooks on commit, and a tabbed left panel.

## Requirements
- **Git** installed and on your `PATH` (the app runs the system `git` for fetch, pull and push).
- Windows needs the WebView2 runtime (included in Windows 11).

## Downloads
- **Windows:** the setup installer (`…_x64-setup.exe`), the MSI, or the standalone `rusty-git-client.exe`.
- **macOS:** the `.dmg`, as built by the release pipeline.
- The builds are **not signed**. Windows SmartScreen shows "unknown publisher" (choose *More info*, then *Run anyway*), and macOS needs right-click, then *Open*, the first time.

## Before you update
- The app's identifier changed, so **saved settings and the recent-repositories list start empty once** (panel widths, diff mode, auto-fetch settings, the start screen's folder). Nothing in your repositories is affected.

## What's new in 0.3.0

### Files tab
- A fourth tab in the left panel lists **every file of the working directory** as a tree of folders (tracked files plus untracked ones that are not ignored). Folders start closed and show how many files they hold; the filter field above narrows the list and opens every folder.
- Files with **uncommitted changes are highlighted** (green new, amber modified, red conflicted), and so are the folders that contain them.
- Click a file to read it in the centre, with line numbers. The right panel is hidden while the tab is open; your half-typed commit message is kept. Binary files and files over 2 MB are not shown.
- **Edit, create and delete files:** *Edit* turns the view into a text editor (**Save** or `Ctrl`/`Cmd` + `S`; line endings are kept), **New file…** is in the tab's "⋯" menu and in a folder's right-click menu (missing folders are created), and **Delete file** asks first. These are plain file changes: they appear in the Changes panel, and Undo does not cover them.
- **Show git history:** right-click a file to list every commit that changed it, and click a commit to see its change to that file.
- **Blame on a line:** click a line and the commit that last changed it appears after the line (short SHA, author, message). Two buttons next to the SHA copy the full SHA, or switch to the Branches tab and show that commit in the graph, selected and scrolled into view.
- **Point an AI tool at code:** Shift+click extends the picked line to a range. **Send to terminal** types a reference such as `@src/app.ts#L12-20` into the terminal's prompt (opening it if needed, without pressing Enter), and **Copy reference** puts it on the clipboard. Both are off while the file has unsaved edits.

### Merge conflicts
- A merge or a merge-pull that hits conflicts is no longer cancelled. The Changes panel shows a **merge banner**, and each conflicted file opens in a **conflict view** where you choose, conflict by conflict, your side, theirs, or both, or edit the result by hand. Whole-file *Use ours / Use theirs* buttons are there too, and **Abort merge** puts everything back.
- This applies to merges and merge-pulls started with a clean working directory. Rebases, cherry-picks and reverts that conflict are still cancelled.

### Commit graph
- **Search** (the button at the right end of the title bar, or `Ctrl`/`Cmd` + `F`): a find bar above the graph that matches commit messages, tag names and SHAs, highlights the hits and steps through them with Enter and Shift+Enter, even far down the history.
- **Tags:** right-click a commit for **Add tag…** (a name for a lightweight tag, plus a message for an annotated one) and **Delete tag**. Tags are local; nothing is pushed.
- The columns (graph, message, author, date, SHA) are under a header row. **Drag** the edge between headers to resize, **double-click** to reset, and **right-click** the header to show or hide columns. Both are remembered.

### Left panel
- The panel is split into **Branches** (local branches and remotes), **Stashes**, **Tags** and **Files** tabs, and the filter field applies to whichever is open. The Tags tab lists every tag, newest first, with an *annotated* marker.

### Committing
- Commits and amends now run your **Git hooks** (`pre-commit`, `commit-msg` and the rest), commit signing and `commit.template`, as they would in a terminal. A hook that rejects the commit shows its output and nothing is committed.
- A **Skip hooks** switch beside Amend runs the next commit or amend with `--no-verify`.
- Rewriting history from the graph (rename, drop, interactive rebase) still does not run hooks.

### Other
- A thin **activity bar** appears on the left panel, the centre and the right panel while that panel is loading or a change is running.
- The branch name in the title bar is cut off with an ellipsis when the window is narrow, and clicking it copies the name.

## Known limitations
- Conflicts in rebases, cherry-picks, reverts and merges started with uncommitted changes are cancelled (the files are named); resolve them in the terminal.
- The Files tab edits plain text only: no syntax highlighting, no renaming or deleting folders, and edits made there are not covered by Undo. A path with spaces is not quoted in a terminal reference.
- Not built yet: pushing tags, unstaging a single line, syntax highlighting and intra-line diff highlighting in diffs.
- Undo and Redo only cover what you do in the app, and only while it is open. Fetch, push and changes to remotes (including deleting remote branches) cannot be undone.
- Dropping, moving or resetting commits needs a clean working directory.
- Switching repository tabs does not keep a tab's open diff, selected commit or terminal session.
- Only English.
